## 4. Review loop (for any new Jules PR)
1. `list_pull_requests`, then check the head SHA, check runs, and `git diff --stat origin/<default>...<head>` for deleted files. Make sure the base commit is an ancestor of the head (`git merge-base --is-ancestor`).
2. Run the #14 section 4 checklist. Locally: `uv sync --extra evals`, Postgres 16 + pgvector (in a cloud session: `service postgresql start`, `apt-get install -y postgresql-16-pgvector`, then create a `rag`/`rag` superuser role and an `rbac_rag` database as the `postgres` user), `RBAC_RAG_TEST_DATABASE_URL=postgresql://rag:rag@localhost:5432/rbac_rag uv run pytest`, plus the PR's own `--fake` command on a fresh database.
3. Issues: post a numbered PR comment AND send the same list to the Jules session (see section 6).
4. All good and CI green on the latest head: squash-merge with `expectedHeadSha` (full 40 characters), close the issue if the PR didn't, tick the wave in #1.

## 5. Lessons learned
- **Squash merges break dependent Jules branches.** Jules merges the pre-squash branch, so the squash commit is not in its history and add/add conflicts follow. Ask for `git merge origin/<default>` and keep the base version of conflicting shared files. If Jules fails twice, ask the owner; a one-time merge commit by a delegated agent (non-force) needs the owner's explicit go-ahead.
- Check what Jules actually pushed with `git merge-base --is-ancestor` and `git merge-tree --write-tree`; GitHub's `mergeable_state` can lag.
- Verify docs by running every command and snippet against the source. In #20, the SQL, data model and a custom `AclFilter` example were wrong until Jules fixed them (the registry calls `cls(settings)` first, then `cls()`).
- A new dependency needs a reason. The `langchain-community<0.4.0` pin was real: ragas 0.4.3 imports `langchain_community.chat_models.vertexai`, removed in 0.4.x.
- Jules copies issue references into `Closes #N`. Both follow-up PRs said `Closes #14` because their issues began "Follow-up from #14". Remove it from the PR body before merging, or #14 (the runbook) auto-closes.
- The local Postgres server in a cloud session can stop between check-ins. If DB tests error with "Connection refused", run `service postgresql start` and re-run before blaming the PR.
- Persona ground truth is `examples/acme/README.md`; it matches `Policy.decide` plus the chunker overrides. No persona can read the "Break-glass access" section under v1 or v2. Canaries match `[A-Z0-9]+-\d{4}`.

## 6. Talking to Jules
Jules API: `https://jules.googleapis.com/v1alpha`, header `X-Goog-Api-Key: $JULES_API_KEY`.
- `GET /sessions?pageSize=N` lists sessions (the same account may have sessions for other repos, such as `gargi-ckg`; ignore those).
- `GET /sessions/{id}` and `GET /sessions/{id}/activities?pageSize=100` show state and progress. The task id in a PR body equals the session id.
- `POST /sessions/{id}:sendMessage` with `{"prompt": "..."}` reaches a finished session; Jules acts on it (typically 20-60 minutes). Write the JSON with `python3 json.dumps` to avoid quoting problems.
